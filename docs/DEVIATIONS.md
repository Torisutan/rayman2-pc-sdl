# Deviations from the original engine structure

Every place where this fork departs from the original module split, names, file layout or data
structures. Each entry gives the place, the change, and why there was no other way.

| # | Where | Change | Why |
|---|---|---|---|
| 1 | `GAM/GAM_init.c` (`FUN_00405a30`), `GAM/pc_winmain.c` (`GAM_pc_fn_WinMain`), `GLI/Init_Gli_helpers.c` (`GLI_pc_fn_vRead/WriteIniString`); `RAYMAN2_LOCAL_UBIINI` | `ubi.ini` is read and written in the working directory (the game folder) instead of the Windows directory (`<windir>\Ubi.ini`, `<windir>\UbiSoft\ubi.ini`). | Current installs ship `ubi.ini` beside the exe and the Windows directory is not writable; without it the graphics DLL is not found. Interim: the per-user location is planned (PLAN "User folder"). |
| 2 | `MMG/MMG_init.c` (`MMG_fn_vInit`, CD drive search `FUN_00448e30`); `RAYMAN2_NO_PROTECTION` | No CD drive search: `g_cCDROM = '.'`, so the engine's CD fallback paths resolve against the working directory. | Copy protection (CD check). |

| 5 | `GAM/GAM_levelload.c` (`GAM_pc_fn_vProtectFlaggedObjects`), `MMG/pc_protect.c` (whole tamper block), `AI/Function.c` (`fn_p_ExecuteVariable`); `RAYMAN2_NO_PROTECTION` | No x86 code from level data (DsgVar arrays) is decrypted or executed; `fn_p_ExecuteVariable` skips its arguments and yields 0. | Copy protection (tamper block). | 7 | `GLI/AdjustCamera.c` (`GLI_xAdjustCameraToViewport2`), new `GLI/GLI_ratio.c`; `RAYMAN2_WIDESCREEN` | Perspective cameras without distortion divide tan(xAlphaX / 2) by the viewport's ratio to 4:3 (Hor+); the adjust also records the screen ratio for the 2D paths. | 8 | `GLI/Object.c` (`GLI_vDraw2DSpriteWithPercent`), `GLI/u_Draw.c` (`GLI_vDraw2DSprite`), `GLI/misc_trivial.c` (`GLI_pc_fn_vWrite16bBitmapToBackBuffer`); `RAYMAN2_WIDESCREEN` | Percent and pixel sprites are mapped into the centred 4:3 band, except sprites spanning the full width (backgrounds, fades). The vignette is squeezed in the bitmap because the renderer DLL in use scales the source by the rect's right edge / 640, so a narrower or wider rect or source does not survive the driver. | 11 | `AGO/AGO.c` (`AGO_vDisplayGAUGES`, `AGO_vDisplayIcones`, `JFFTXT_vAffiche`, `AGO_fn_vComputeSafeAreaAnchors`), `GLI/GLI_ratio.c` (`GLI_fn_vComputeSafeAreaAnchors`, `GLI_fn_vSetSafeAreaAnchorOfBox`, `GLI_fn_xToSafeArea`); `RAYMAN2_WIDESCREEN` | While the engine is not frozen (the original's own test for the in-game HUD; the pause menu freezes it), the gauges, icons and strings of the frame are grouped where their boxes touch (gap up to 1 % of the 4:3 layout). Everything else stays in the band (row 8). | Wide display modes: the HUD (health bar, lum and cage counters) belongs at the screen corners, not at the corners of the 4:3 band. | 13 | `GLI/GLI_pc.h` (`GLI_fnl_InitDll`'s binding), new `GLI/GLI_linkdrv.c`; `USE_GLI_DX6`, CMake `R2_GLI_DX6` | The Direct3D 6 renderer driver (`GliDX6vf.dll/` sources) is linked into the exe. | 14 | `GAM/pc_winmain.c` (Win32 blocks fenced `#ifndef USE_SDL`), new `GAM/sdl_main.c`; `USE_SDL`, CMake `R2_USE_SDL` | The window comes from SDL and the engine loop runs on the main thread: no engine thread, the engine events are flags, window events are pumped before every frame and while paused. Requests the engine posted to the window thread (display mode change, activation) are SDL user events served there. ERM message boxes take ERM's no-window path. Not carried over: the minimum window size, pausing on caption clicks, the power-suspend handling (one thread: the system suspends the process). | Original console structure (engine loop called directly), needed for GL contexts bound to one thread and for targets without Win32. |
| 15 | `GLI/cpu_timer.c`, `GLI/timer_sub2.c` (PC timer functions fenced `#ifndef USE_SDL`), new `TMR/sdl_timer.c`, `TMR/sdl_timer.h`; `USE_SDL` | The timer channels come from SDL: channel 0 from SDL's millisecond count, channels 1 and 2 from SDL's performance counter (channel 2 is the CPU time stamp counter on PC, its rate measured by a one-second busy wait at init). The system timer period is SDL's (1 ms by default). | Original console structure (the platform file gives the same timer functions); the time stamp counter is x86-only and nothing in the exe or the Direct3D 6 driver reads channel 2. |
| 16 | `INO/INO.c` (DirectInput parts fenced `#ifndef USE_SDL`), new `INO/sdl_ino.c`, `INO/sdl_ino.h`; `USE_SDL` | Keyboard, mouse and gamepads come from SDL. Key codes stay DirectInput's (the level data and options use them); SDL's keyboard state is mapped to them. Gamepads go through SDL's mapping table and appear as DirectInput shows an XInput gamepad (ten buttons, X/Y/Rx/Ry); other joysticks are not offered, the triggers (DirectInput's shared Z axis) are unused until their direction is checked, and gamepads plugged in after start are not seen (as with DirectInput's enumeration at init). Key characters (`wLastASCII`, read by nothing outside INO) come from SDL's keymap: a dead key gives its character, the keypad decimal gives `.` on every layout. Mouse: four buttons and the wheel in `WHEEL_DELTA` units, as DirectInput's mouse format; axis ranges are not queried. | DirectInput exists on Windows only; SDL's gamepad mapping covers the other targets with one layout. |
| 17 | new `WAVMWBVR.dll/src/mixer/sndmix_pc.c` (C branch of the sample driver's mixer, without `OPTIMIZED_FOR_MMX_WITH_ASM`: the default of the linked drivers on every target) | The C branch keeps the mixer's delay lines in its own arrays with their full extent (the asm reads them across the bounds of the arrays `sndwave.c` declares, which lie back to back only in the retail image) and gives its own values where the asm reads outside them: zeros in front of the send ring (the reverb window after `vMixMono16StepSend` wrapped its cursor; retail: the voice array), zeros for the three `sndwave.c` variables behind the swept comb ring (reached only with a sweep delay below 0x20, after the comb voice set it), delay 0 for comb slots above 3 (retail: the variables after the 4-entry table). The send cursor starts at the ring head (retail: a null address, so a reverb pass before the first send would fault), and `vMixStereo16Native`'s stale register on a voice end in its first block is 0 (retail: whatever the MMX registers hold). Everything else is byte-equal to the asm, checked call for call. | Those values are other data of the retail image or register contents; a portable build has neither the layout nor the registers. |
| 18 | new `GliGL3vf.dll/` (OpenGL 3.3 driver module, CMake `R2_GLI_GL3`), `GAM/sdl_main.c` (`fn_ulDriverWindowFlags`) | A second renderer driver beside Direct3D 6, built as a module (`DLL/GliGL3vf.dll`) and chosen by `ubi.ini` as the retail drivers are.
